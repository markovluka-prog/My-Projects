# Рыцари и Замки — Контекст проекта

Технический контекст: архитектура, стек, структура, кампания, ИИ.
Для обзора игры см. [description.md](description.md).

## Стек и платформа

| Слой | Технология |
|------|-----------|
| Клиент | HTML5 + JavaScript (ES, сборка **Vite** → `assets/index-*.js`) |
| Графика | Canvas/DOM + спрайты Tiny Swords |
| PWA | `manifest.webmanifest`, standalone, landscape, тема `#1a1410` |
| Десктоп | macOS-обёртка **SwiftHTMLRunner** (нативный контейнер для HTML) |
| Бэкенд | **Supabase** (`https://cxhpcmgtvuhxhqhjryth.supabase.co`) |
| Аутентификация | Supabase Auth: email+пароль, Google OAuth |
| Онлайн | Supabase (комнаты, очередь, синхронизация ходов, реванш) |

## Источник истины: `story.txt`

Файл `story.txt` — внешний конфиг, читаемый игрой. Содержит две секции:

### 1. ИИ-пресеты (7 уровней сложности)
Градация: **Новичок → Ученик → Боец → Воин → Тактик → Мастер → Легенда**.

Каждый пресет задаёт ~25 параметров поведения ИИ:
- `frameWait` — задержка «обдумывания» (35 → 6, чем меньше тем быстрее);
- `randomMoveChance`, `mistakeChance`, `skipChance` — доля случайных/ошибочных/
  пропущенных ходов;
- `threatBlindness` — «слепота» к угрозам;
- `spellReluctance` — нежелание кастовать;
- `useMinimax` + `minimaxDepth` — поиск (0 → глубина 4 у «Легенды»);
- `focusFireWeight`, `comboDetection`, `territoryWeight`, `aggressionBias`;
- `positioningWeight`, `flanking`, `resourceControl`, `defensiveFormation`,
  `unitSynergy`, `trapSetting`, `adaptiveDifficulty`.

«Легенда» — финальный босс: minimax depth 4, подстраивается под игрока
(`adaptiveDifficulty=true`), используется **один раз** за кампанию.

### 2. Сюжет (кампания)
Формат строки: `ПресетАИ | Название задания`. Структура:

**Глава 1 — Меч в камне** (знакомство с механиками, ошибки прощаются)
- Юность Артура: Безвестный оруженосец, Турнир в Лондоне, Меч в камне
- Корона Логрии: Непокорные бароны, Клятва верности, Битва при Бедегрейне
- Эскалибур: Владычица Озера, Дар Эскалибура

**Глава 2 — Рыцари Круглого стола** (контроль территории; пик — первый Тактик)
- Камелот: Основание Камелота, Круглый стол, Сэр Ланселот
- Войны с саксами: Саксонское вторжение, Гора Бадон, Двенадцать битв
- Честь рыцаря: Гавейн и Зелёный рыцарь, Турнир чемпионов

**Глава 3 — Закат Камелота** (Грааль и предательство; провал сложности → рост)
- Поиски Грааля: Священный Грааль, Сэр Галахад, Тень измены, Предательство Ланселота
- Битва при Камлане: Мордред восстаёт (намеренно легче — король ослаблен),
  Осада Камелота, Последний поход, Король былого и грядущего

> Кривая сложности спроектирована намеренно: в начале гл.3 сложность снижается
> («эмоциональная передышка»), затем резко растёт к финалу.

## Боевые сущности (из бандла)

- **Юниты**: Рыцарь, Лучник, Арбалетчик, Конный (кавалерия), Катапульта,
  Самурай / Тяжёлая пехота. Параметры: `hp`, `damage`, `range`, `moves`, `cost`.
- **Веса ИИ по ролям**: `knightTankWeight`, `cavalryFlankWeight`, `archerKiteWeight`.
- **Предметы**: оружие и броня (Кольчуга, Латы, Солнечный меч, Синий лук,
  Посох огня, Волшебная палочка, Солнечные часы…), крафт из артефактов.
- **Заклинания**: только с башни мага; «Кавалерийский натиск», «Дождь защиты»,
  «Небо огня» и др.; есть `damageBuff`.
- **Победа**: захват вражеского замка.

## Онлайн-инфраструктура

Состояния из кода: подключение к матчу, ожидание соперника, отправка/
синхронизация хода, восстановление партии, реванш, обработка дисконнекта
(«Соперник отключился — вы победили!»), очередь подбора, комнаты по коду.

Бэкенд — Supabase: Auth (email/Google), хранение сессий, realtime-обмен ходами.

## Известные ограничения контекста

- Логика игры доступна только в минифицированном виде — точные числовые
  балансовые значения юнитов/заклинаний надо вытаскивать из `index-*.js`
  или из оригинальных исходников (если они есть отдельно).
- Supabase URL и публичный ключ зашиты в клиент (норма для anon key, но
  проверь RLS-политики — см. [bugs.md](bugs.md)).
