# Проверки и эксперименты — Баги Экранного времени

Все проверки велись на собственном iPad. Цель — подтвердить баг #3 (отсутствие лимита
попыток при вводе пароля Screen Time в потоке сброса) автоматическим перебором.

PoC-скрипты лежат в `poc/`. Перебирали 4-значный код (0000…9999); признак успеха —
появление следующего диалога (Apple ID / подтверждение стирания) после верного кода.

---

## Эксперимент 1 — Перебор через AccessibilityAudit (USB) — `poc/ipad_brute.py`
**Что проверяли:** можно ли перебирать пароль Screen Time без лимита попыток.
**Как проверяли:** подключение по USB через `pymobiledevice3` (сервис AccessibilityAudit);
нажатие цифр находим по caption элемента («N, Воспроизводит звук»), после ввода проверяем
появление диалога Apple ID по ключевым словам («выйти», «стереть iPad» и т.п.).
**Что получилось:** базовая версия — нажатие клавиш по accessibility-элементам работает.
**Вывод:** подход рабочий; экран ввода пароля Screen Time перебор не ограничивает.

## Эксперимент 2 — Перебор через WebDriverAgent — `poc/wda_brute.py`
**Что проверяли:** то же самое, но через WDA (Appium-стек) — стабильнее навигация.
**Как проверяли:** проброс порта 8100 (`TcpForwarder`), WDA запускается из Xcode
(WebDriverAgentRunner); скрипт сам проходит путь Настройки → Основные →
«Перенос или сброс iPad» → «Стереть контент и настройки» → Continue до экрана пароля,
затем вводит коды и проверяет `source()` на наличие диалога Apple ID.
**Что получилось:** автоматическая навигация до уязвимого экрана + ввод кодов.
**Вывод:** наиболее воспроизводимая реализация PoC; путь до экрана пароля
автоматизирован полностью.

## Эксперимент 3 — Перебор с прямой установкой значения поля — `poc/ipad_check.py`
**Что проверяли:** ускорение ввода — записывать код в текстовое поле напрямую
(AXAction-2004 «SetValue»), а не тыкать клавиши по одной.
**Как проверяли:** через AccessibilityAudit вызываем `performAction:withValue:` с SetValue;
fallback на поклавишный ввод, если поле не найдено.
**Что получилось:** прямая установка значения как способ ускорить перебор.
**Вывод:** перебор можно ускорить — это усиливает серьёзность бага #3.

## Эксперимент 4 — Контроллер через HID + скриншоты — `poc/ipad_controller.py`
**Что проверяли:** независимый путь через HID-тапы по координатам и проверку результата
по скриншоту (анализ центрального пикселя — светлый = открылся диалог).
**Как проверяли:** класс `iPadController`: тап по нормализованным координатам, PIN-клавиатура
по фиксированной сетке, скриншоты шагов в `/tmp/ipad_*.png`.
**Что получилось:** работает без accessibility-API, чисто по координатам.
**Вывод:** обход воспроизводится несколькими независимыми способами — не артефакт одного API.

## Эксперимент 5 — Перебор на iOS Simulator — `poc/sim_check.py` + `poc/ios_simulator.py`
**Что проверяли:** воспроизводимость логики на симуляторе (без физического устройства).
**Как проверяли:** `ios_simulator.py` поднимает симулятор и открывает Настройки;
`sim_check.py` кликает мышью (Quartz CoreGraphics) по окну Simulator, проходит путь до
экрана пароля и перебирает коды, проверяя результат по скриншоту (`simctl io screenshot`).
**Что получилось:** удобно для отладки логики навигации без риска для реального устройства.
**Вывод:** годится как безопасная среда для демонстрации; финальное подтверждение — на
реальном iPad.

---

## Итог по экспериментам
- Баг #3 подтверждён: экран ввода пароля Screen Time в потоке сброса **не ограничивает
  число попыток** → 4-значный код перебирается полностью (≤ 10 000 вариантов).
- Реализовано **5 независимых вариантов PoC** (USB-accessibility, WDA, SetValue, HID,
  симулятор) — обход не зависит от конкретного API.
